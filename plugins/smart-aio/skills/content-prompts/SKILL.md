# Smart AIOプロンプトを使用する

Smart AIOのプロンプト本文を修正、要約、改善、整形しない。誤字、表記揺れ、改行、記号を含めて `content-v1` を正本として扱う。

## 実行手順

1. `node scripts/content_prompt_registry.mjs verify` を実行し、6プロンプトの文字数・SHA-256、組み立て規則、正本ファイルのSHA-256を確認する。1件でも不一致なら制作を停止する。
2. [保護プロンプト対応表](references/content-map.md)を読み、処理に対応する `prompt_key` と組み立て規則を特定する。
3. `node scripts/content_prompt_registry.mjs get <prompt_key>` でプロンプト原文を取得する。
4. `assembly-rules.json` に定義された変数置換と末尾追記だけを、記載順に適用する。
5. 現在の会話内でプロンプトを実行する。OpenAI APIは呼び出さない。
6. 結果に `prompt_version=content-v1`、`prompt_key`、登録済みSHA-256を記録する。

## 変更禁止

- プロンプト本文へ、新システム用の説明、顧客ID、権限、保存先、レビュー基準を追記しない。
- 読みやすさを理由に改行、箇条書き、敬語、変数名を変更しない。
- 組み立て規則にない置換、再構成、ルール追加を行わない。
- 原文に矛盾や誤字があっても勝手に直さず、問題を報告する。
- チェックサム不一致、必要入力不足、対応する組み立て規則不明の場合は実行しない。

## 新システム側の処理

次の処理は保護プロンプトの外側で行う。

- `client_id` の確定と顧客間分離
- 担当者権限の確認
- 一次情報、ニュース、過去記事の対象顧客限定
- 実行ID、ロック、監査ログ
- Driveとスプレッドシートの保存先制御

保護プロンプトへ渡す入力データを作る前に上記を完了し、別クライアントの情報が1件でも含まれる場合はプロンプトを実行しない。

## 正本

- プロンプト原文: `../../references/content-v1/prompts.json`
- 組み立て規則: `../../references/content-v1/assembly-rules.json`
- チェックサム: `../../references/content-v1/manifests/SHA256SUMS`

プロンプト本文を更新するときは、管理者承認、SHA-256再検証、全テスト合格を経て新しいバージョンとして保存する。組み立て規則はSmart AIO Skillランタイムだけが実行する。
