# 一次情報取得

出典と事実を切り離さず、あとから確認できる形で返す。

## 優先順位

1. 顧客が登録した承認済み資料
2. 官公庁、法令、統計、企業公式発表
3. 業界団体、製品公式文書
4. 信頼できる報道機関

## 手順

新規クライアント登録では、クライアント名と公式サイトURLを受け取ったら、追加質問より先に公式URLを取得する。現在のアプリで利用できるWeb取得またはブラウザー機能を使い、リダイレクト後の公開ページ本文を抽出する。保護プロンプトへ渡す本文は先頭8,000文字とし、取得できない場合だけ利用者へテキスト提供を依頼する。

記事企画前は、同じ公式ドメインのサイトマップ、記事一覧、サイト内検索で公開記事のタイトルとcanonical URLを収集し、`publishedSiteArticles` として対象クライアントだけに紐づける。候補と近い公開記事があってもここでは除外しない。タイトル、URL、一致した検索意図または主題を `$article-production` へ渡し、「このまま進める」「別記事にする」の選択画面を出せるようにする。

1. 登録済み顧客では `client_id`、記事テーマ、必要な事実、情報の基準日を確認する。新規登録ではクライアント名の最初の `_` より前を標準規則の `client_id` として自動取得し、それ以外で `client_id` を確定できない場合だけ停止する。
2. SMARTAIO本番Drive直下の対象クライアントフォルダーで、そのクライアント専用の `01_一次情報` フォルダーと利用者権限を確認する。顧客マスターファイルは必須にしない。
3. フォルダー内の `${client_id}_${クライアント名}_一次情報台帳` を正本として開く。存在しない場合は `prepare-client-source-register` でテンプレートからヘッダーだけの空台帳を作る。公式サイトは基本情報調査に使うが、一次情報台帳へ自動登録しない。
4. 検索条件へ必ず同じ `client_id` を付け、一次情報台帳で機密区分、利用可否、確認者、有効期限を確認する。`利用可否=利用可`、`確認者` が空欄・要確認・未確認ではない、依頼と同じ `client_id`、期限内の行だけを記事制作へ渡す。
5. 取得した事実ごとに `client_id`、`source_id`、URLまたはDrive URL、公開日、取得日を付ける。新しい一次情報を受け取った場合は同じ台帳の新しい行へ記録する。
6. 同じ主張を複数資料で確認できる場合は、同一クライアント内の資料だけを併記する。
7. 出典がない主張、期限切れ、引用禁止、別クライアントの資料は除外する。
8. 返却前に全件の `client_id` が依頼と一致することを確認する。不一致が1件でもあれば全件を返さず停止する。
9. 記事へ使える事実、要確認、使わない情報を分けて返す。

## 出力

各項目を一次情報台帳の16列へ記録する。AI内部の返却は `client_id`、`fact`、`source_id`、`source_location`、`published_at`、`obtained_at`、`usage_status`、`note` を維持する。詳細は [出典ルール](references/source-rules.md) を参照する。
