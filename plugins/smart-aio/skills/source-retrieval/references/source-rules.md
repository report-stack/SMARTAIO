# 出典ルール

一次情報の識別子は `client_id + source_id` とする。同じ `source_id` が別クライアントに存在しても別資料として扱う。検索、保存、返却の全段階で `client_id` を必須にする。

`usage_status` は `利用可`、`要確認`、`利用不可`。日付や数値は資料の記載単位を保つ。記事本文へ反映する事実には必ず同じクライアントの `client_id` と `source_id` を付ける。

新規顧客の台帳はデータ行0件で開始する。顧客から一次情報を受領した後に新しい行へ登録し、最初は `要確認` とする。担当者または検証担当が確認者を記録し、利用可否を `利用可` に変更した後だけ記事へ渡す。`確認者` が空欄、`要確認`、`未確認` の行は、利用可否が誤って `利用可` になっていても使用しない。

一次情報の正本は、各クライアントの `01_一次情報` フォルダーにある `${client_id}_${クライアント名}_一次情報台帳` とする。シート名は `一次情報台帳`、列順は `client_id`、`source_id`、`情報種別`、`タイトル`、`一次情報・事実`、`出典URL／Drive URL`、`資料内の場所`、`公開日`、`取得日`、`有効期限`、`利用可否`、`機密区分`、`使用上の注意`、`登録者`、`確認者`、`最終更新日` から変更しない。

記事企画はクライアント別記事制作シートの `記事一覧`、作業状態は同シートの状態、内部リンク関係は `記事一覧` と `クラスター` で管理する。`02_記事企画`、`05_内部リンク`、`90_作業中` フォルダーは作成・使用しない。

公的資料を複数クライアントで使う場合も、各クライアントの一次情報台帳へ別々に登録し、利用許可と表現条件を顧客ごとに持つ。共通箱から直接記事へ使わない。
