# Smart AIO記事レビュー

決定的チェックとAIの内容レビューを分離して行う。本文作成時の保護プロンプトは変更しない。

## 4段階レビュー

1. `DIRECTION`: 検索意図、対象読者、記事の目的、記事カテゴリ、ハッシュタグ、独自性、実現可能性を確認する。
2. `OUTLINE`: タイトルの訴求力と本文整合、結論、見出し、責任範囲、根拠計画、内部リンク計画、カテゴリ・タグ整合を確認する。
3. `DRAFT`: 本文、一次情報、数値、固有名詞、検索意図、読みやすさを確認する。
4. `FINAL`: 本文・内部リンク網・構造化マークアップ・図解・画像・出力形式・Doc本文のタグ表示を完成物として確認する。内部リンクは本文末尾の関連記事枠ではなく本文中の自然な設置文に入っているか、図解はDoc本文の色付け箇所に含まれる概念から外れず、本文にない説明や判断項目を追加していないかを確認する。図解元本文は短文・項目の羅列やキャプションだけではなく、前後の本文と自然につながる通常段落であり、その直後に図解画像が置かれていることを確認する。図解元本文は図解の読み方や意図の説明文ではなく、図解画像にした内容そのものを本文として述べ、本文と図解の項目・順序・意味が一致していることを確認する。意味を変えない短いラベル化は許可し、見やすい図として成立していることを優先する。さらに原寸画像をID-00012相当の基準画像と比較し、タイトルまたは文脈見出し、補足文、視線誘導、情報階層、画面利用率、文字品質、判断結果または結論を評価する。低密度、ラベルとアイコンの単純列、85点未満は重大違反として `REVISE` にする。

`DIRECTION`、`OUTLINE`、`DRAFT` はAI合格後に自動で次工程へ進む。`FINAL` 合格後だけ、人による完成物の `FINAL_APPROVAL` を待つ。

## 実行順序

1. `client_id`、記事ID、本文、記事企画、同じ顧客の過去記事、一次情報台帳、顧客ルールを集める。
2. `node scripts/review_article.mjs input.json` を実行し、顧客混入、重複、責任ラベル、記事カテゴリ、ハッシュタグ、根拠、リンク、構造化マークアップ、図解画像、禁止表現、年号、形式を機械判定する。
3. 重大違反があればAI採点へ進まず、修正対象を返す。
4. 作成時と異なる `review_run_id` で、`prepare-stage-review` と `evaluate-stage-review` を実行する。
5. [AIレビュー基準](references/quality-rubric.md) を使い、段階ごとの観点を100点で採点する。`DIRECTION` と `OUTLINE` では [記事タイトル品質基準](../article-production/references/title-quality.md) も読み、検索語・読者課題・具体的価値・本文整合を評価する。過去レビューの指摘は同じ顧客・同じ段階だけを渡す。
6. 機械判定とAI採点を統合し、重大違反0、機械チェック全件合格、記事総合80点以上、図解視覚品質85点以上だけを `PASS` とする。図解評価は作成と異なる `review_run_id` で行い、原寸確認した図解SHAを保存対象SHAと一致させる。
7. `REVISE` の場合は問題箇所、理由、修正案を示す。保護プロンプトを変更せず、段階成果物だけを修正対象にする。
8. 結果をレビュー台帳へ記録する。`DIRECTION`、`OUTLINE`、`DRAFT` は合格後に自動進行し、`FINAL` だけ人の最終承認を待つ。AIだけで公開しない。

## AIレビュー出力

- `client_id`
- `article_id`
- `result`: `PASS` または `REVISE`
- `total_score`: 0〜100
- `critical_violation`: true または false
- `category_scores`: 事実性、検索意図、顧客適合、重複、内部リンク、図解一致、形式、カテゴリ・タグ整合
- `issues`: 問題箇所、理由、修正案
- `sources_checked`: 確認した `source_id`
- `reviewed_at`
- `diagram_visual_quality`: `review_run_id`、`reviewer_model`、`inspection_method=ORIGINAL_IMAGE_VISUAL_INSPECTION`、`reviewed_diagram_sha256`、基準画像、品質点、画面利用率、必須品質チェック

## 停止条件

- 別顧客のデータが混ざっている。
- 記事企画または本文がない。
- `DIRECTION` または `OUTLINE` で記事カテゴリまたはハッシュタグが未確認。`FINAL` でGoogleドキュメント本文のタグ表示、本文中の自然な内部リンク設置文、内部リンク網、構造化マークアップ、図解画像、図解元本文の色付け、図解元本文が自然な通常段落である証拠、図解元本文が図解内容そのものである証拠、図解画像が図解元本文の直後に置かれている証拠、図解内テキストが本文由来である証拠、図解SHAに結び付いた独立視覚品質レビューのいずれかがない。
- 図解視覚品質が85点未満、画面利用率が65%未満または95%超、必須品質チェックに1件でも不合格がある、低密度、または項目名とアイコンを並べただけである。
- 一次情報の利用可否を確認できない。
- 保護プロンプトの変更を修正方法として提案しようとしている。
- `producer_run_id` と `review_run_id` が同じで、独立レビューになっていない。
